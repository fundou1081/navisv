## 实现优先级 (精简版)

### 第一轮 (1-2周)

**① uncertain 节点显式标记 (P1-3)**
- `NodeAttr` 有 `confidence` 字段，图上 uncertain 用虚线边框 + "?" 标注
- 改动小，立竿见影

**② 时钟/复位扇出统计 (P1-2)**
- 收集所有 `timing='state'` 边的时钟信号
- 统计每个时钟驱动的寄存器数量
- 新增 CLI: `navisv clock-stats design.sv`

**③ CDC 路径列表 (P1-1)**
- 基于 `TimingAnalyzer._reg_graph`
- 识别所有源时钟域 ≠ 目标时钟域的路径
- 输出: `navisv cdc design.sv` → CDC 路径表格

### 第二轮 (2-3周)

**④ 跨模块路径标注 (P2-1)**
- 模块边界节点用特殊形状 (e.g. box with double border)
- 路径跨模块时边用虚线

**⑤ 约束 → Coverage 代码生成 (P2-2)**
- `conditions_to_coverage_suggestions()` 输出可直接粘贴的 covergroup 代码段
- 而不只是文本建议

**⑥ 边层级标注 (P2-4, 新增)**
- 图上每条边标注"第几跳"或路径深度

### 第三轮 (长期, 待定)

**⑦ RTL diff** — 改动前后影响范围对比 (P3-1)

## 待讨论

1. **CDC 路径列表**: 要不要加"安全级别"？(SAFE/UNSAFE/CRITICAL)
   - 如果要，需要定义规则。目前可以先只列路径不打分。
2. **约束 → Coverage**: 输出形式是"文本建议"还是"可直接运行的 covergroup 代码"？后者需要语法正确性验证。
3. **跨模块路径**: 现在 navisv 的模块实例边界追踪已经做到什么程度？有没有可以测试的真实多模块设计？
4. **图的自动化**: 要不要在 CI 里自动更新 PNG 并推送到 GitHub Pages？
